## 4. Avalie especificamente a compatibilidade Local-First

Para cada entidade sincronizável, classifique qual estratégia parece mais apropriada:

* Sincronização simples;
* Histórico/versionamento;
* Append-only;
* Soft delete/tombstone;
* Conflito que pode ser combinado automaticamente;
* Conflito que exige decisão do usuário;
* Não sincronizar inicialmente.

Considere que:

* O Mobile deverá funcionar 100% localmente sem conta;
* A sincronização com a nuvem será opt-in;
* Não aceitaremos `last-write-wins` silencioso para informações médicas relevantes;
* Um registro criado offline deverá manter o mesmo identificador depois da sincronização;
* Web e Mobile poderão alterar dados em momentos diferentes;
* Precisamos preservar histórico quando clinicamente relevante.

## 5. Avalie o que deve e o que NÃO deve ir para o Mobile

O aplicativo Mobile NÃO será uma cópia da aplicação Web.

A Web continuará sendo a experiência mais completa para desktop.

O Mobile deve ser extremamente simples e orientado às tarefas mais frequentes, especialmente para usuários leigos e idosos.

Avalie as funcionalidades existentes e classifique-as em:

* **MVP Mobile**
* **Mobile posterior**
* **Somente Web**
* **Precisa de decisão de produto**

Para o MVP Mobile, considere prioritariamente a seguinte jornada:

**Primeiro uso → cadastrar usuário quando necessário → cadastrar familiar/paciente → consultas a agendar → receitas/medicamentos → exames a agendar/acompanhar**

Entretanto, no modo **“Somente neste aparelho”**, não obrigue conceitualmente o usuário a criar conta na nuvem antes de começar a utilizar o aplicativo.
